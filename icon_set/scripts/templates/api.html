Connection & login

Examples use the production URL above. Change it to http://127.0.0.1:8000 for your local server.

API calls need no login, including reviews, edits, and generation. Without a valid reviewer session, actions are attributed to system. With a reviewer session, actions are attributed to that reviewer. Send JSON with Content-Type: application/json; browser requests must use the same origin. The page only builds commands; it does not send write requests.

Login is optional and only identifies reviewer actions. To act as a reviewer, log in below, then add --cookie cookies.txt to your request. Without that cookie, the request acts as system.

Ready, Disapproved, and Approved may transition directly to each other with POST /api/reviews. They can also be rejected. Restore rejected icons with POST /api/reject-combination/restore to return them to Ready before approving or disapproving.

Returning to Ready clears existing feedback. Approval applies to the exact current SVG hash. Always read the current icon before writing. Failed builds are separate from review status and cannot be approved through the normal review endpoint.

Read icons by stage

GET /gallery/icons.json returns icons and failed_icons. Review state is read separately from GET /api/reviews, a map from icon key to current status. Join them by key. This example uses jq to select Ready icons; change the status to pending, approve, or rejected.

For type-filtered reads, GET /api/icon-types?type=uploaded&status=disapprove returns uploaded icons needing fixes. This endpoint uses disapprove in its status field and filter, while /api/reviews uses pending.

Revise an icon at a review stage

  1. Read GET /api/icon-artwork?icon=…. Keep the top-level svg_sha256 (the original source hash) and choice.revision, or 0 if no choice exists.
  2. Save an SVG candidate with POST /api/icon-artwork, action: "upload", the current source_mode, original hash, revision, filename, and SVG contents. This saves a candidate without changing the displayed version or review decision.
  3. Read the updated revision. Select the saved SVG with source_mode: "use_upload" and no action. Selecting artwork also approves it. Restore a rejected icon before selecting artwork.
  4. Read the current catalog hash again. To send the new displayed version back to review, write status: "ready" with that hash.

Use use_org to restore the original or use_edited for accepted browser geometry (requires edit_revision). SVG-only uploads support manual SVG revisions; authored primitive editing and AI fixes require geometry or Python source.

Icon types can be changed through POST /api/icon-type. Category is accepted on initial upload. There is currently no general name/category update endpoint.

Create an icon family

Custom families are supported for SVG uploads and human review. List built-in and custom families with GET /api/icon-families. Create a family with POST /api/icon-families, then use its id as family in POST /api/icons/upload.

{"id":"rounded","name":"Rounded icons","canvas_size":48}

The id must start with a lowercase letter and contain only lowercase letters, digits, underscores or hyphens (1–64 characters). Name is required (1–120 characters). Canvas size is an integer from 16 to 256; SVG viewBox must be 0 0 N N for that size. Success returns 201 {"family":{...}}; an existing id returns 409; invalid fields return 400. No login is required; browser requests must use the same origin.

The five built-in families are sub (32), symbol (32), solo (48), combination_main (48), and container (64). Custom families persist with the review database through restarts and builds, including empty families. Family creation does not add Python authoring contracts or AI generation support. Icons retain type uploaded; category is a separate optional topic. Uploads enter Ready and use the existing approval and feedback endpoints. Family renaming, resizing and deletion are not currently exposed.

Generation enters the same review pipeline

Submit POST /api/generation and poll GET /api/generation. A generated candidate is not yet a reviewed library icon. Accept it with POST /api/generation/accept using its job id; acceptance adds it to Ready. Discarding a candidate uses /api/generation/discard. Sessionless calls are attributed to system.

New SVG uploads use POST /api/icons/upload and immediately enter Ready. They receive type uploaded and default category manual_upload. bypass_validation defaults to true; false runs SVG hole-and-pinch QA. Safety, canvas, and rendering checks always run. See the upload guide for canvas sizes and validation scope.

Responses & conflicts

CodeMeaning / next step
200 / 201Read or write succeeded; reviews return the stored status.
202Generation operation accepted; inspect the job for completion.
400Invalid payload. Read the returned error.
401Incorrect credentials on an optional login attempt.
403Browser origin does not match the server.
404Unknown icon or route.
409Stale SVG hash/revision, or rejected icon needs restoration. Read again before deciding.
413 / 415Request too large / expected JSON content type.
422Optional upload QA failed. No icon saved; inspect validation.
503Storage or validator unavailable. Check the server before retrying.

A successful review returns {"saved": true, "status": "approve", "updated_by": "…"}. Errors normally return {"error": "…"}. Never reuse an old approval hash for new artwork.
