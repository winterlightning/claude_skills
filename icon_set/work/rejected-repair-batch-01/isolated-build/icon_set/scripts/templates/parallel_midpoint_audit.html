Parallel lines · midpoint audit

Core validation now blocks undersized parallel gaps. Each straight run sends a perpendicular ray from its midpoint in both directions, stopping at the nearest parallel segment. Minimum: 8 centerline units = 4 ink-clearance units with a 4-unit stroke. Core validation also uses the positive-overlap fallback for midpoint misses.

How to read this audit and its limitations

Exact parallel directions only, including diagonal lines. Contiguous collinear pieces within one path are merged. Curves and dots are excluded. Rays seek other finite parallel lines; they do not stop on intervening curves or nonparallel geometry. Tied nearest hits are retained. Connections are shown for review rather than automatically exempted.

Red rays are below 8; green rays meet the minimum. Blue marks the selected source; orange marks the target. Distance is measured centerline to centerline, then 4 is subtracted for ink clearance. Touching a target endpoint is labeled. Collinear overlaps are listed separately.

Midpoint blind spot: staggered parallel segments can overlap even though neither midpoint faces the other. These are separately identified using overlap analysis, not claimed as midpoint detections. Farther pairs hidden by nearer parallel segments are also recorded separately in the JSON. This parallel rule uses 8 for all families; each profile’s general spacing threshold is shown for comparison.
