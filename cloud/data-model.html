The pipeline

One idea ties the system together: a concept is what someone searches for, a physical is the form that expresses it, an icon is an approved drawing of that form, and a release is the frozen set users rely on.

Vocabulary

Every term used in code, data and conversation. Colors match the layers in later diagrams.

ConceptA meaning; what someone searches for.
love, parking, upload
PhysicalA recognizable form, independent of how it is drawn. Single (heart) or composite (cloud-on-monitor).
heart, cloud, shield
IconOne drawing design of a physical, in one form.
solo/heart-a
PrimitiveFull-size icon (48), complete on its own, not a combination.
SubiconSmall icon (32), used only inside side combinations, never alone.
ContainerA frame that hosts content (64).
shield, screen, speech bubble
SymbolContent placed inside a container (32).
check mark in a shield
CombinationAn icon assembled from other icons. Side: main + subicon at a corner. Container: container + symbol at the center.
VariantAlternative designs of the same physical that exist at the same time.
cloud with 2 bumps vs 3 bumps
RevisionOne exact version of an icon over time, identified by its SVG sha256. Never changed.
ReferenceAn original source SVG, used as evidence. Never shipped.
ReleaseA frozen, versioned set of approved revisions.

Rules

  • Meaning lives only on physicals: icon → physical → concept. Adding "favorite" to heart makes every heart icon findable.
  • A different design of the same form is a variant; a different form (broken heart) is a different physical.
  • If a drawing splits into two independent forms it is a combination; if it is one inseparable form it is a physical.
  • Form (primitive, subicon, container, symbol) belongs to the icon: check can have a primitive, a subicon and a symbol.

Core model

Many-to-many between meaning and form; one-to-many from form to drawings to versions.

Composites: two levels

A combination is described abstractly as a composite physical (what it is made of — searchable, stable) and concretely as a combination icon (which drawings — renderable, swappable).

Side combination
exactly one main (primitive) + one sub (subicon) at tl · tr · bl · br.
Container combination
exactly one container + one symbol at center.
Consistency
a combination icon's parts must be icons of its composite physical's parts. Combinations are one level deep.
Rebuilds
when cloud-a gets a new revision, revision_parts lists every combination built from the old one.

Open decisions

#QuestionCurrent assumption
1Is primitive vs subicon two separate forms, or is a subicon a kind of primitive?Separate forms of an icon
2Is a side combination's main the reused primitive, or a special combination_main drawing?Reused primitive
3Can combinations nest?No — one level deep
4Are combination SVGs assembled, hand-drawn, or both?Assembled; hand-drawn allowed as a revision
5Which variant does search return?A default per physical, overridden by a style set
6One canonical concept ID — how to merge UUID, name key and icon_id?One-time merge, reviewed
7Store stroke graph in D1 or only SVG?Both: graph JSON + SVG in R2
8Licensing of Lucide and other referencesRecord per reference before shipping
